# What the HTTP/2 codec enforces of RFC 9113

**Status:** describes what shipped (version 0.0.0).

`ghttp_h2_*` (`h2frame.h`, `h2conn.h`) is HTTP/2 as bytes in and bytes out, for a
client or a server, on top of the HPACK codec described in `hpack.md`. It opens
no socket, speaks no TLS, reads no clock: the caller feeds bytes, writes the
output, and may give the connection a millisecond tick so that per-interval
limits renew. Each rule below is tested; test names in `tests/unit/test_h2*.cpp`
are sentences, and the oracle differential (`make check-oracle`) compares the
connection with nghttp2, h2 (Python) and Go's `x/net/http2`.

Every decision is taken on a whole frame (and, for the connection preface, byte
by byte), so the events and the output are identical however the input is cut.
`make test` sweeps every split of each scenario, and the fuzzer cuts at points
its input chooses.

## Connection errors and stream errors

A connection error is returned by `ghttp_h2_conn_feed()` (`ERR_CORRUPT` for a
violation, `ERR_LIMIT` for a limit, `ERR_OOM`); the GOAWAY carrying the code
(section 5.4.1) is already in the output; the connection stays failed. A stream
error is an event, the RST_STREAM is in the output, and the connection goes on.
`ghttp_h2_conn_finish()` says whether the transport's end of input fell on a
frame boundary.

## Enforced

### Start (section 3.4)

- The client preface is `PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n`, checked octet by
  octet: the first wrong octet is a PROTOCOL_ERROR however the input was cut,
  and an HTTP/1 request in its place is refused at once. The `Upgrade: h2c`
  path does not exist (it was removed from the protocol).
- The first frame from the peer must be SETTINGS. This library advertises
  `ENABLE_PUSH=0`, and a server that sets it to 1 is a PROTOCOL_ERROR.

### Frames (section 4, section 6)

- Header: 24-bit length, type, flags, 31-bit stream id with the reserved bit
  dropped. A length over our `max_frame_size` is a FRAME_SIZE_ERROR judged
  from the header alone, before any payload is buffered. Wrong fixed sizes
  (PING 8, RST_STREAM 4, WINDOW_UPDATE 4, PRIORITY 5, SETTINGS a multiple of
  6, an ACK with a payload) carry the error the RFC names; a stream or
  connection error as the frame's stream id decides.
- Padding: its length may not reach the payload (PROTOCOL_ERROR). Padding of
  DATA counts against the flow-control window and is returned at once.
- Stream id rules per type: DATA, HEADERS, PRIORITY, RST_STREAM and CONTINUATION
  need a stream; SETTINGS, PING and GOAWAY need stream 0; a violation is a
  PROTOCOL_ERROR.
- Unknown frame types are accepted whole and handed to the extension handler;
  unknown flags are ignored (section 4.1, section 5.5).
- SETTINGS (section 6.5.2): each value in range (`ENABLE_PUSH` 0 or 1,
  `INITIAL_WINDOW_SIZE` at most 2^31-1 as FLOW_CONTROL_ERROR, `MAX_FRAME_SIZE`
  16384 to 2^24-1). Applied when received, acknowledged, and ours applied when
  the peer's ACK arrives. A changed `INITIAL_WINDOW_SIZE` adjusts every open
  stream, may make a window negative, and a result above 2^31-1 is a
  FLOW_CONTROL_ERROR. A change to `HEADER_TABLE_SIZE` is announced in the next
  block this endpoint sends. An unknown identifier goes to the handler.
- PING is answered with the same data. GOAWAY is reported with its last stream
  and debug data; `ghttp_h2_conn_shutdown()` sends one and refuses later streams.
  The last stream id of a GOAWAY never rises (section 6.8): it names the highest
  stream accepted for processing (a stream whose header block was refused, or
  never completed, is not named), and a later GOAWAY, including the one a
  connection error sends, repeats it or lowers it. A received GOAWAY whose id
  is higher than the one before is a PROTOCOL_ERROR. A client is told of every
  stream above the id of a received GOAWAY by one `GHTTP_H2_EVENT_STREAM_UNPROCESSED`
  event each (in ascending order, in the calls to `ghttp_h2_conn_feed()` after
  the GOAWAY event), so the application can retry them on another connection;
  frames that still arrive for those streams are discarded.

### Header blocks (section 4.3, section 6.2, section 6.10)

- A HEADERS block and its CONTINUATIONs are joined and decoded whole. Any other
  frame between them, or a CONTINUATION on another stream or with nothing to
  continue, is a PROTOCOL_ERROR; an extension frame inside a block as well.
- A block that fails to decode is a connection error COMPRESSION_ERROR, because
  the table is shared. A block for a stream we refuse (concurrency limit, or one
  we reset) is still decoded so that the table stays in step. That includes a
  stream the application resets with `ghttp_h2_conn_reset_stream()` while its
  HEADERS and CONTINUATION frames are still arriving: the rest of the block is
  decoded and dropped.
- CONTINUATION frames per block, encoded octets per block, fields per block,
  decoded list size and one field are each capped; the ones that count frames
  stop at the limit plus one (the CVE-2024-27316 class).

### Stream states (section 5.1)

- A client's stream ids are odd and rise; skipping is allowed and closes the
  skipped ones. DATA, RST_STREAM, WINDOW_UPDATE or CONTINUATION on an idle
  stream is a PROTOCOL_ERROR.
- DATA or HEADERS on a half-closed (remote) stream is a stream error
  STREAM_CLOSED; on a closed stream it is a connection error, except for the
  frames that arrive before the peer has seen our RST_STREAM, which are
  discarded (but flow-control counted, and a header block is still decoded). A
  small ring of closed streams (`max_closed_streams`) tells these apart.
- WINDOW_UPDATE, RST_STREAM and PRIORITY on a closed stream are ignored.
- The ring is finite. A late frame for a stream the ring has forgotten (an id
  at or below the highest id it has dropped) is discarded, with its DATA
  credited, instead of being judged as an error: the stream was open once and
  how it ended is not remembered. A stream id that was skipped and is above
  that mark is still a PROTOCOL_ERROR (section 5.1.1). The default ring (512)
  is larger than the default rapid-reset limit (200).
- Concurrency (`max_concurrent_streams`, `max_streams`) refuses the stream with
  REFUSED_STREAM.

### Flow control (section 5.2, section 6.9)

- Receiving: a DATA frame bigger than the connection window is a connection
  FLOW_CONTROL_ERROR, bigger than the stream window a stream error; the whole
  frame, padding included, counts against the connection even when its stream
  errs. Credit is returned automatically, or by `ghttp_h2_conn_consume()` when
  `manual_flow_control` is set.
- Sending: `ghttp_h2_conn_send_data()` takes only what both windows allow and
  the peer's frame size, and says how much; END_STREAM takes effect only when
  all of the data was accepted; an empty final DATA needs no window. A
  WINDOW_UPDATE of 0 is a stream error on a stream and a connection error on
  stream 0; one that would overflow 2^31-1 is a FLOW_CONTROL_ERROR.

### Messages (section 8)

- Field names are lower case tokens; connection-specific fields (`connection`,
  `proxy-connection`, `keep-alive`, `transfer-encoding`, `upgrade`) and `te`
  other than `trailers` make the message malformed, as do missing, duplicate
  or misplaced pseudo-header fields, a pseudo-header in trailers, an
  empty `:path`, and a `:status` that is not three digits. Malformed is a
  stream error PROTOCOL_ERROR and the connection goes on.
- `content-length` is checked against the DATA received, except for a response
  to HEAD and a 204 or 304 (section 8.1.1). A body over `max_body_bytes` is a
  stream error.
- A response's interim (1xx) sections, final section and trailers are told
  apart; an interim response may not end the stream.
- A Host field beside `:authority` must say the same (compared ignoring case),
  or the request is malformed; a request with more than one Host field, one of
  which differs, likewise. A response with DATA frames that carry data to a
  request that was HEAD, or with status 204 or 304, is a stream error
  PROTOCOL_ERROR (an empty DATA frame that ends the stream is fine).
- A request maps to `GHTTP_Request` (`Host` is added from `:authority` and
  split `cookie` fields are joined with `; `, section 8.2.3), a response to
  `GHTTP_Response`.
- CONNECT (section 8.5) makes the stream a tunnel: its DATA is not framed
  against `content-length`. See Extended CONNECT below for what a tunnel is.

### Extended CONNECT and tunnels (RFC 8441, section 8.5)

`SETTINGS_ENABLE_CONNECT_PROTOCOL` (0x8) is known to the connection, no longer
an unknown setting for the extension handler.

- **The setting.** It defaults to 0 and a server sends 1 only when
  `GHTTP_H2Limits::enable_connect_protocol` is set (the default leaves a server
  as it was). A client cannot set the limit (`ghttp_h2_conn_create()` is
  `GHTTP_ERR_INVALID`). A connection error PROTOCOL_ERROR is the answer to: a
  value other than 0 or 1; the setting from a client with the value 1 (it is a
  server's setting); a change from 1 to 0. A client's 0 is ignored, with no error and no
  change of state (Python's `h2` sends it in every client's first SETTINGS). Repeating
  1 is allowed. The peer's value is in
  `ghttp_h2_conn_peer_settings()` and the SETTINGS event reports it.
- **The request.** A request with `:protocol` is an Extended CONNECT: it needs
  `:method CONNECT`, `:scheme`, `:path` and `:authority`, and the `:path` is
  checked as for any other request. `:protocol` on any other method, with a
  member missing, with a value that is not a token (optionally `token/token`, the
  shape of an Upgrade token), repeated, after a regular field, or at a
  server that did not send the setting, is malformed: a stream error
  PROTOCOL_ERROR, the connection goes on. A value over `max_protocol_bytes`
  (64) is a stream error ENHANCE_YOUR_CALM; the field limits of the decoder still
  apply first and end the connection. A plain CONNECT is unchanged: `:scheme`
  or `:path` without `:protocol` is malformed. The value is reported
  (`GHTTP_H2Event::protocol`, `ghttp_request_protocol()`) and never interpreted.
  The request's target is the `:path`; `Host` is added from `:authority`.
- **A client** may send one (`ghttp_request_set_protocol()` on the request) only
  after the server's SETTINGS enabled it: before that `ghttp_h2_conn_send_request()`
  is `GHTTP_ERR_INVALID`; `ghttp_h2_conn_can_send_extended_connect()` says.
  The pseudo-header fields are written in the order of the RFC's examples
  (`:method`, `:protocol`, `:scheme`, `:path`, `:authority`).
- **The tunnel.** A server's stream for a CONNECT, and a client's stream once a
  2xx has answered its CONNECT, is `GHTTP_H2_STREAM_TUNNEL` (the HEADERS event
  says `tunnel`). Its DATA is opaque: no `content-length` and no
  `max_body_bytes`; the windows apply as to any stream. END_STREAM from one side
  half-closes it (the DATA or HEADERS event says `end_stream`; the other side
  may go on), RST_STREAM aborts it and the code is in the STREAM_RESET event,
  trailers are malformed. A tunnel counts as a stream toward
  `max_concurrent_streams`, `max_streams` and the closed-stream memory, and its
  resets toward `max_rst_per_interval`, so opening and resetting tunnels is
  rapid reset.

### What is sent

`ghttp_h2_conn_send_request()`, `_send_response()` and `_send_trailers()` return
`GHTTP_ERR_INVALID`, change nothing and open no stream for what HTTP/2 cannot
carry: a target form the method does not take (authority-form except for
CONNECT, `*` except for OPTIONS, origin- or absolute-form for CONNECT), an
absolute-form target with no authority or with userinfo under http or https, a
scheme that is not an RFC 3986 scheme, an empty or non-token field name (a
pseudo-header name included), a value with NUL, CR or LF or with a space or tab
at either end, a connection-specific field, `te` other than `trailers`, more
than one Host field, or a Host that differs from the target's authority. A
Host field is carried as `:authority` and never also as a regular field. A
fragment of the target is dropped.

### Limits are checked at creation

`ghttp_h2_conn_create()` returns `GHTTP_ERR_INVALID` for limits with a `size` of
zero (an uninitialised struct), with `max_buffered_bytes` below
`max_frame_size + 9` (input and output share that one limit, so a whole frame
must fit), or with a zero in a field that bounds a header section, the streams
or the interval. A shorter struct (an older caller) takes the defaults for the
fields it lacks.

### Abuse limits (all stop at the limit plus one unit)

SETTINGS, PING, RST_STREAM (rapid reset, CVE-2023-44487), PRIORITY, frames of
unknown types, and WINDOW_UPDATE frames for streams that no longer exist, each
per interval; DATA frames with no data and no END_STREAM in a row (only HEADERS,
or DATA with data or END_STREAM, ends the run: a PING between them does not);
octets buffered (a partial frame, a header block being gathered, and output
nobody drains). The RST_STREAM count includes the resets this endpoint sends
because of what the peer sent (a malformed request, a refused stream), not
those the application asks for. The per-interval counts renew only when the
caller ticks (a clock that runs backwards also starts a new interval); a
caller that never ticks gets each of these as a cap on the connection's whole
life. The code sent is ENHANCE_YOUR_CALM, and the result `ERR_LIMIT`.

### Outputs of `ghttp_h2_conn_feed()`

`*consumed` and `*event` are written on every return (the event is zeroed, with
its size, unless something was reported), so neither is ever stale.

## Not enforced, or not provided

- **No push.** `ENABLE_PUSH=0` is advertised and PUSH_PROMISE is a PROTOCOL_ERROR.
  The refusal is one function, `h2_refuse_push`.
- **No priority scheme** (section 5.3 is deprecated). PRIORITY is parsed, its size
  checked, and ignored in every state; one function, `h2_handle_priority`.
- **No use of `:protocol`**: it is validated and reported (Extended CONNECT,
  above) and what it names is the application's: WebSocket is `ws_h2.h`;
  WebTransport, CONNECT-UDP and CONNECT-IP get the plumbing and nothing more.
  No `Upgrade`, no HTTP/3 (RFC 9220) or QPACK.
- **No scheduler.** What to write next, among streams, is the caller's choice.
- **No transport rules:** TLS version and cipher requirements and ALPN (section
  9.2), connection reuse and 421 (section 9.1.1), idle timeouts and
  PING-based liveness. The clock only renews counts.
- **No semantic validation beyond framing**: the value of `:scheme`, the shape
  of the `:path` and the authority are those of the shared message types and
  not interpreted further, as in the HTTP/1.1 codec.

## Extension seams

Each exists now and is unused, so that adding the feature later is a local
change:

- **Unknown frames and settings** reach `ghttp_h2_conn_set_extension_handler()`,
  and `ghttp_h2_conn_send_extension_frame()` writes one (never a defined type, never longer than the peer accepts).
- **A stream mode** (`GHTTP_H2_STREAM_MESSAGE`, `GHTTP_H2_STREAM_TUNNEL`), set by
  CONNECT (plain or extended) or by `ghttp_h2_conn_set_stream_mode()`, for
  opaque data past message framing; `ws_h2.h` joins one to a WebSocket.
- **Push** and **priority** are one function each (above).
- **Settings, limits and events** begin with a `size` and carry reserved
  members; zero them via the `_default()` functions.
- **Shared layers**: field and message types are the HTTP/1.1 ones with nothing
  h2-specific in them; Huffman and integer coding sit in `coding.c`.
